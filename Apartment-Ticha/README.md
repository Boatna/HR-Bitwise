# ระบบบริหารหอพักพนักงาน (Employee Dormitory Management System) v2.1

ระบบบริหารจัดการหอพักพนักงานองค์กรแบบเข้าใจง่าย ไม่ซับซ้อน ใช้งานผ่านเว็บเบราว์เซอร์ เชื่อมต่อฐานข้อมูล Google Sheets ผ่าน Google Apps Script Web API

---

## 🌟 จุดประสงค์หลักของระบบ (Core Objectives)

ระบบนี้ออกแบบมาเพื่อตอบโจทย์การใช้งานจริงของ HR อย่างตรงไปตรงมา:
1. **เก็บข้อมูลว่าพนักงานคนไหนพักอยู่ห้องไหน (Employee Occupancy):** เช็คอิน ย้ายห้อง และเช็คเอาท์ได้สะดวกรวดเร็ว ป้องกันการเช็คอินซ้อน (พนักงาน 1 คน มีห้องพัก Active ได้ห้องเดียว)
2. **ตรวจสอบว่าห้องพักว่างหรือเปล่าแบบ Real-time (Room Vacancy Status):**
   - 🟢 **ว่าง (Available):** ยังไม่มีผู้พัก (0 คน) พร้อมให้พนักงานเข้าพักได้ทันที
   - 🟡 **ว่างบางส่วน (Partially Occupied):** มีผู้พักแล้ว แต่ยังไม่เต็มความจุห้อง (เช่น พัก 1 คน จากความจุ 2 คน)
   - 🔴 **เต็ม (Full):** มีผู้พักเต็มตามความจุของห้อง
   - 🟠 **ปิดปรับปรุง (Maintenance):** ห้องอยู่ระหว่างปิดซ่อมบำรุง สามารถกดสลับเปิด/ปิดได้ในคลิกเดียว
3. **ระบบการจองที่จอดรถ (Parking Management):**
   - บันทึกชัดเจนว่า **ที่จอดรถแต่ละช่องเป็นของใคร (พนักงานคนไหน)** และ **พักอยู่ห้องใด**
   - รองรับทั้งรถยนต์ (Car) และรถจักรยานยนต์ (Motorcycle)
   - บันทึกเลขทะเบียนรถ ยี่ห้อ/รุ่น โซน และวันที่เริ่มจอง
   - มีระบบจองช่องจอด คืนช่องจอด และอัปเดตห้องพักให้อัตโนมัติเมื่อพนักงานย้ายห้อง
4. **เฟอร์นิเจอร์มาตรฐานเหมือนกันทุกห้อง:** ทุกห้องพักมีชุดเฟอร์นิเจอร์มาตรฐานและเครื่องปรับอากาศครบชุดเหมือนกันทั้งหมด จึงไม่มีความจำเป็นต้องกรอกหรือบันทึกทะเบียนทรัพย์สินแยกรายชิ้นให้ยุ่งยาก

## 🔒 ฐานข้อมูล Google Sheets (Database Schema)

โครงสร้างฐานข้อมูลออกแบบให้เข้าใจง่าย ประกอบด้วย **7 ตาราง**:

| แผ่นงาน (Sheet) | ข้อมูลที่จัดเก็บ |
|:---|:---|
| **`Rooms`** | ข้อมูลห้องพัก (รหัสห้อง, อาคาร, ชั้น, เลขห้อง, ประเภทห้อง, ความจุ, เพศผู้พัก, ค่าเช่า, สถานะ, หมายเหตุ) *ทุกห้องมีเฟอร์นิเจอร์มาตรฐานครบชุด* |
| **`Employees`** | ข้อมูลพนักงาน (รหัสพนักงาน, คำนำหน้า, ชื่อ, นามสกุล, ชื่อเต็ม, แผนก, ตำแหน่ง, โรงงาน, เบอร์โทร, อีเมล, สถานะ) |
| **`Occupancy`** | ข้อมูลการเข้าพักจริง (รหัสการเข้าพัก, รหัสพนักงาน, รหัสห้อง, รหัสเตียง, เลขเตียง, วันที่เข้าพัก, วันที่ย้ายออก, สถานะ, หมายเหตุ) |
| **`Parking`** | ข้อมูลการจองที่จอดรถ (รหัสช่อง, เลขช่องจอด, โซน, ประเภทรถยนต์/มอเตอร์ไซค์, สถานะ, รหัสพนักงานผู้จอง, รหัสห้องพัก, เลขทะเบียนรถ, รุ่น/ยี่ห้อ, วันที่เริ่มจอง, หมายเหตุ) |
| **`Buildings`** | ข้อมูลอาคารหอพัก (รหัสอาคาร, ตัวย่ออาคาร, ชื่ออาคาร, ที่ตั้ง, จำนวนชั้น, สถานะ, หมายเหตุ) |
| **`Settings`** | การตั้งค่าระบบ (ชื่อหอพัก, องค์กร, รายการเฟอร์นิเจอร์มาตรฐาน, อีเมล) |
| **`AuditLog`** | ประวัติการทำรายการในระบบ (รหัสล็อก, เวลา, อีเมลผู้ใช้, การกระทำ, โมดูล, รหัสรายการ, หมายเหตุ) |

## 🚀 ขั้นตอนการติดตั้งและเชื่อมต่อระบบ (Setup Guide)

### ขั้นตอนที่ 1: สร้างฐานข้อมูล Google Sheets อัตโนมัติ
1. ไปที่ [Google Sheets](https://sheets.new) เพื่อสร้าง Spreadsheet ว่างใหม่ 1 ไฟล์
2. ตั้งชื่อไฟล์ตามต้องการ เช่น `Dormitory_Database_Bitwise`
3. ไปที่เมนู **ส่วนขยาย (Extensions)** > **Apps Script**
4. ลบโค้ดเดิมใน Apps Script ออกทั้งหมด
5. คัดลอกโค้ดจากไฟล์ `google-apps-script/setup_sheets.gs` ไปวาง
6. เลือกฟังก์ชัน **`setupDormitoryDatabase`** ที่แถบเครื่องมือด้านบน แล้วกดปุ่ม **เรียกใช้ (Run)**
7. กดยืนยันการอนุญาตสิทธิ์ (Review Permissions) เมื่อมีป๊อปอัปแจ้งเตือน
8. ระบบจะสร้างแผ่นงานครบทั้ง 7 ตารางพร้อมข้อมูลตัวอย่างเริ่มต้นทันที

---

### ขั้นตอนที่ 2: ติดตั้ง Web API Backend (`Code.gs`)
1. ในหน้าต่าง Google Apps Script เดิม ให้เพิ่มไฟล์ใหม่ชื่อ `Code` (เครื่องหมาย + > Script) แล้วคัดลอกโค้ดจากไฟล์ `google-apps-script/Code.gs` ไปวาง (เก็บ `setup_sheets.gs` ไว้ในโปรเจกต์เดียวกันได้ ไม่ชนกัน)
   - แนะนำ: เปิด **Project Settings** แล้วติ๊ก "Show appsscript.json" วางค่าจาก `appsscript.json` และตั้งเขตเวลาเป็น `Asia/Bangkok`
2. กดปุ่มบันทึก (ไอคอนแผ่นดิสก์ หรือ `Ctrl+S`)
3. คลิกปุ่มสีน้ำเงิน **ทำให้ใช้งานได้ (Deploy)** ที่มุมขวาบน > เลือก **การทำให้ใช้งานได้ใหม่ (New deployment)**
4. คลิกไอคอนฟันเฟือง ⚙️ ด้านซ้าย > เลือกประเภท **เว็บแอป (Web app)**
5. ตั้งค่าดังนี้:
   - **คำอธิบาย (Description):** `Dormitory API v2.1 with Parking`
   - **ดำเนินการในฐานะ (Execute as):** **ฉัน (Me)**
   - **ผู้มีสิทธิ์เข้าถึง (Who has access):** **ทุกคน (Anyone)** *(สำคัญมาก เพื่อให้หน้าเว็บเรียก API ได้โดยไม่ต้องล็อกอินบัญชี Google)*
6. คลิกปุ่ม **ทำให้ใช้งานได้ (Deploy)**
7. คัดลอก **URL เว็บแอป (Web app URL)** ที่ได้มา (รูปแบบ: `https://script.google.com/macros/s/XXXXX/exec`)



> **อัปเดตจากเวอร์ชันเก่า (มีข้อมูลจริงอยู่แล้ว):** ห้ามรัน `setupDormitoryDatabase` ซ้ำ (จะลบข้อมูล) ให้วางโค้ด `Code.gs` ใหม่ → รันฟังก์ชัน **`ensureAllSheets`** 1 ครั้งเพื่อสร้างตารางที่ขาด (เช่น `Parking`) → **Deploy > Manage deployments > ไอคอนดินสอ > Version: New version > Deploy**
> (ถ้าไม่ออกเวอร์ชันใหม่ Web App จะยังรันโค้ดเก่าและ URL เดิมจะใช้ต่อได้)

---

### ขั้นตอนที่ 3: นำ API URL มาใส่ในระบบ Frontend
1. เปิดหน้าเว็บ `admin.html` บนเบราว์เซอร์
2. ไปที่เมนู **การตั้งค่า (Settings)** ด้านซ้าย
3. วาง Web App URL ที่ได้จากขั้นตอนที่ 2 ลงในช่อง "Web App URL"
4. กดปุ่ม **"บันทึก URL เชื่อมต่อ"** และสามารถกด **"ทดสอบการเชื่อมต่อ"** เพื่อตรวจเช็คความพร้อม
5. ระบบจะบันทึก URL ไว้ในเบราว์เซอร์ของคุณ และเชื่อมต่อกับ Google Sheets ทันที!

## 🛡️ กฎการทำงานของระบบ (Business Logic)

1. **คำนวณสถานะห้องอัตโนมัติ:** สถานะห้องจะคำนวณจากจำนวนคนเข้าพักจริงเทียบกับความจุห้อง และสถานะปิดปรับปรุง เสมอ
2. **ห้ามเช็คอินซ้อน:** พนักงาน 1 คน มีห้องพัก Active ได้เพียงห้องเดียวเท่านั้น หากต้องการเปลี่ยนห้อง ให้ใช้ปุ่ม "ย้ายห้อง" (Transfer)
3. **ระบบที่จอดรถเชื่อมโยงกับห้องพัก:** เมื่อจองที่จอดรถ ระบบจะดึงห้องพักของพนักงานให้อัตโนมัติ และเมื่อพนักงานย้ายห้อง ระบบจะอัปเดตห้องพักในรายการที่จอดรถให้โดยอัตโนมัติ
4. **ปิดปรับปรุงในคลิกเดียว:** ผู้ดูแลสามารถกดสลับสถานะ "ปิดปรับปรุง / เปิดใช้งาน" ได้โดยตรงจากหน้าห้องพัก โดยห้องที่ปิดปรับปรุงจะแสดงเป็นสีส้มและไม่อนุญาตให้เช็คอิน
5. **การย้ายออก (Check-out):** เมื่อกดเช็คเอาท์ ระบบจะบันทึกวันที่ย้ายออก คืนสถานะห้องให้กลายเป็นห้อง "ว่าง" และ **คืนช่องจอดรถของพนักงานให้อัตโนมัติ**
6. **กติกาที่จอดรถ:**
   - จองได้เฉพาะพนักงานที่ "พักอยู่ในหอ" (มีห้อง Active) ห้องพักในรายการจองดึงจากการเข้าพักจริงเสมอ
   - 1 พนักงานจองได้ 1 ช่องต่อประเภท (รถยนต์ 1 + มอเตอร์ไซค์ 1) และ 1 ทะเบียนจองได้ช่องเดียว
   - เลขช่องจอดห้ามซ้ำ ช่องที่มีผู้จองลบ/เปลี่ยนประเภทไม่ได้ ต้องคืนช่องก่อน
   - ย้ายห้อง → ห้องในรายการจอดอัปเดตเอง / ลบพนักงาน → คืนช่องให้อัตโนมัติ
   - ช่องที่ผู้จองไม่ได้พักอยู่แล้ว (เช่น แก้ข้อมูลใน Sheets เอง) จะขึ้นแถบเตือน "ควรคืนช่อง"
7. **กติกาเพศของห้อง:** ห้องที่กำหนดเป็นชาย/หญิง จะไม่รับพนักงานที่คำนำหน้าชื่อไม่ตรง (นาย = ชาย, นาง/นางสาว = หญิง) ห้อง "ไม่จำกัด" รับได้ทุกคน
8. **ห้องที่ปิดปรับปรุง/ไม่เปิดใช้งาน** ไม่นับเป็นที่ว่างใน KPI และไม่แสดงในรายการเลือกห้องของเช็คอิน/ย้ายห้อง

## 🅿️ Parking API (Google Apps Script Actions)

| Action | หน้าที่ |
|:---|:---|
| `getParking` | รายการช่องจอดทั้งหมด พร้อมชื่อผู้จอง แผนก เบอร์โทร ห้อง อาคาร ทะเบียน |
| `saveParkingSlot` | เพิ่ม/แก้ไขช่องจอด (เลขช่อง โซน ประเภท สถานะ) |
| `assignParking` | จองช่องจอดให้พนักงาน (ดึงห้องพักอัตโนมัติ) |
| `releaseParking` | คืนช่องจอด |
| `deleteParkingSlot` | ลบช่องจอด (ได้เฉพาะช่องที่ไม่มีผู้จอง) |

- "ที่ว่าง" ใน KPI นับรวมห้องปิดปรับปรุง → ไม่นับแล้ว, เพิ่มสถานะ "ไม่เปิดใช้งาน" ให้ทำงานจริง
- ตรวจสอบเพิ่ม: พนักงานต้องมีอยู่จริงก่อนเช็คอิน, เพศห้อง, วันที่ออกต้องไม่ก่อนวันที่เข้า, ย้ายห้องซ้ำห้องเดิม, เลขห้อง/รหัสพนักงาน/เลขช่องจอดซ้ำ, ลดความจุต่ำกว่าผู้พักปัจจุบัน
- วันที่: แก้ปัญหาวันเพี้ยนจาก timezone (Sheets→JSON, `toISOString` ได้วันเมื่อวานช่วงเช้ามืด) และ `bedId` ที่ขึ้นเป็น `BED-BED-...`
- เบอร์โทร/รหัสพนักงานที่ขึ้นต้นด้วย 0 ไม่ถูกแปลงเป็นตัวเลขอีก; เขียนข้อมูลลง Sheets เร็วขึ้น (เขียนทั้งแถวทีเดียว)
- Export CSV กัน formula injection; `setupDormitoryDatabase` ถามยืนยันก่อนลบข้อมูลเดิม; แผ่นงานที่ขาดสร้างด้วยหัวคอลัมน์ที่ถูกต้อง
- เพิ่มคลาส CSS ที่ขาด (`text-orange`, `fs-7` ฯลฯ), ลบ `@import` ฟอนต์ซ้ำ, ล้างพารามิเตอร์ใน URL หลังเปิดป๊อปอัปจากหน้าผังห้อง

> ⚠️ ข้อควรทราบด้านความปลอดภัย: Web App ตั้งเป็น "Anyone" และฝั่งหน้าเว็บยังไม่มีระบบล็อกอิน ผู้ที่ทราบ URL สามารถเรียก API ได้ ควรเก็บ URL เป็นความลับ หรือพิจารณาเพิ่มระบบยืนยันตัวตนหากใช้งานจริงในวงกว้าง
