## 🌟 จุดเด่นของระบบ (Key Features)

1. **การคำนวณสถานะห้องพักแบบ Real-time (Business Rule 27):**
   - ห้ามกรอกจำนวนผู้พักหรือสถานะห้องโดยตรง
   - คำนวณจากสถานะงานซ่อม (`Maintenance`) และข้อมูลการเข้าพักจริง (`Occupancy`) ร่วมกับจำนวนเตียงที่เปิดใช้งาน (`Beds`):
     - 🟢 **ว่าง (Available):** ไม่มีผู้พักอาศัย (0/N)
     - 🟡 **ว่างบางส่วน (Partially Occupied):** มีผู้พักแต่ยังมีเตียงว่าง (1/N)
     - 🔴 **เต็ม (Full):** เตียงเต็มตามจำนวนเปิดใช้งาน (N/N)
     - 🟠 **ปิดปรับปรุง (Maintenance):** ห้องอยู่ระหว่างปิดซ่อมบำรุง
     - ⚪ **ไม่เปิดใช้งาน (Inactive):** ห้องที่ไม่มีเตียงเปิดใช้งาน
2. **ผังสถานะห้องพัก (Floor Plan View):**
   - แสดงผลแยกตามอาคารและชั้น
   - ระบุเตียงว่าง-เตียงเต็มด้วยจุดสถานะของแต่ละเตียง
   - กรองตามอาคาร ชั้น เพศ สถานะ และค้นหาตามเลขห้องหรือชื่อผู้พัก
3. **Admin Dashboard & Visualizations:**
   - KPI ภาพรวม: ห้องว่าง, เตียงว่าง, อัตราเข้าพัก (Occupancy Rate)
   - กราฟ Chart.js ครบ 8 รายการ
   - แถบความหนาแน่นการเข้าพักแยกตามอาคาร (Heatmap)
   - แจ้งเตือนห้องใกล้เต็ม (เหลือ 1 เตียงสุดท้าย)
4. **กระบวนการจัดการการเข้าพัก (Occupancy Workflows):**
   - **Check-in:** ตรวจสอบความพร้อมของเตียงว่าง และป้องกันพนักงานเช็คอินซ้อน
   - **Check-out:** ตรวจสอบการคืนกุญแจ สภาพห้อง และบันทึกประวัติก่อนคืนสถานะเตียงว่าง
   - **Room Transfer (ย้ายห้อง):** ย้ายเตียงโดยไม่ลบประวัติเดิม ปิด Occupancy เก่าและสร้าง Occupancy ใหม่พร้อม Audit Trail
5. **ระบบความปลอดภัยและการควบคุม (Single-Admin & Audit Trail):**
   - โหมดบริหารจัดการสำหรับ **ผู้ดูแลระบบคนเดียว (Single-Admin Mode)** ลดขั้นตอนและสิทธิ์ที่ไม่จำเป็น
   - สิทธิ์เต็มทุกโมดูล จัดการได้โดยตรงแบบ Fast Action
   - บันทึก Audit Log ทุกการสร้าง แก้ไข ลบ เช็คอิน เช็คเอาท์ และย้ายห้อง เพื่อเป็นหลักฐานย้อนหลัง

## 🚀 ขั้นตอนการติดตั้งและเชื่อมต่อระบบ (Setup Guide)

### ขั้นตอนที่ 1: สร้างฐานข้อมูล Google Sheets อัตโนมัติ (18 ตาราง)
1. เปิดเบราว์เซอร์ไปที่ [Google Sheets](https://sheets.new) เพื่อสร้าง Spreadsheet ว่างใหม่ 1 ไฟล์
2. ตั้งชื่อไฟล์ตามต้องการ เช่น `Dormitory_Database_Bitwise`
3. ไปที่เมนู **ส่วนขยาย (Extensions)** > **Apps Script**
4. ลบโค้ดเดิมในโปรเจกต์ Apps Script ออกทั้งหมด
5. คัดลอกโค้ดจากไฟล์ `google-apps-script/setup_sheets.gs` ไปวาง
6. เลือกฟังก์ชัน **`setupDormitoryDatabase`** ที่แถบเครื่องมือด้านบน แล้วกดปุ่ม **เรียกใช้ (Run)**
7. กดยืนยันการอนุญาตสิทธิ์การเข้าถึงข้อมูล (Review Permissions)
8. ระบบจะสร้างแผ่นงานครบทั้ง 18 แผ่นงานพร้อมข้อมูลตัวอย่างเริ่มต้นทันที

---

### ขั้นตอนที่ 2: ติดตั้ง Web API Backend (`Code.gs`)
1. ในหน้าต่าง Google Apps Script เดิม ให้ลบโค้ดในตัวแก้ไขออก แล้วคัดลอกโค้ดจากไฟล์ `google-apps-script/Code.gs` ไปวางแทนที่
2. กดปุ่มบันทึก (รูปแผ่นดิสก์ หรือ `Ctrl+S`)
3. คลิกปุ่มสีน้ำเงิน **ทำให้ใช้งานได้ (Deploy)** ที่มุมขวาบน > เลือก **การทำให้ใช้งานได้ใหม่ (New deployment)**
4. คลิกไอคอนฟันเฟือง ⚙️ ด้านซ้าย > เลือกประเภท **เว็บแอป (Web app)**
5. ตั้งค่าดังนี้:
   - **คำอธิบาย (Description):** `Dormitory API v1.0`
   - **ดำเนินการในฐานะ (Execute as):** **ฉัน (Me)**
   - **ผู้มีสิทธิ์เข้าถึง (Who has access):** **ทุกคน (Anyone)** *(สำคัญเพื่อให้ GitHub Pages สามารถเรียก API ได้)*
6. คลิกปุ่ม **ทำให้ใช้งานได้ (Deploy)**
7. คัดลอก **URL เว็บแอป (Web app URL)** ที่ได้มา (จะมีลักษณะ `https://script.google.com/macros/s/XXXXX/exec`)

---

### ขั้นตอนที่ 3: นำ API URL มาใส่ในระบบ Frontend
1. เปิดหน้าเว็บ `index.html` หรือ `admin.html` บนเบราว์เซอร์
2. หากยังไม่ได้ใส่ URL ระบบจะแสดงแถบสีเหลืองด้านบนเตือนว่ายังไม่ได้เชื่อมต่อ
3. คลิกปุ่ม **"ใส่ API URL"** หรือเข้าไปที่เมนู **Admin > การตั้งค่า (Settings)**
4. วาง URL ของ Google Apps Script Web App ที่ได้จากขั้นตอนที่ 2 แล้วกดบันทึก
5. ระบบจะรีเฟรชหน้าเว็บและดึงข้อมูลจริงจาก Google Sheets ขึ้นมาแสดงผลทันที!

---

### ขั้นตอนที่ 4: การนำขึ้นโฮสต์บน GitHub Pages
1. ทำการ Push โค้ดทั้งหมดขึ้น GitHub Repository (เช่น `employee-dormitory`)
2. ไปที่ **Settings** ของ Repository บน GitHub
3. เลือกเมนู **Pages** ที่เมนูด้านซ้าย
4. ในหัวข้อ **Build and deployment > Source** เลือก **Deploy from a branch**
5. เลือก Branch: `main` และ Folder: `/(root)` แล้วกด **Save**
6. ภายใน 1-2 นาที คุณจะได้ URL สำหรับเปิดใช้งาน เช่น `https://username.github.io/employee-dormitory/`

|:---:|:---|:---|
| 1 | `Employees` | ข้อมูลพนักงาน รหัส ชื่อ นามสกุล แผนก โรงงาน เบอร์โทร อีเมล |

| 3 | `Floors` | ข้อมูลชั้นในแต่ละอาคาร |

| 5 | `Beds` | ข้อมูลเตียงในห้อง รหัสเตียง หมายเลขเตียง ประเภท สถานะ |
| 6 | `Occupancy` | ข้อมูลการเข้าพักจริง (ใครพักห้องไหน เตียงไหน วันที่เข้า-ออก สถานะ Active) |
| 7 | `RoomRequests` | คำขอเข้าพักจากพนักงาน รอการอนุมัติจาก Admin |
| 8 | `RoomTransfers` | ประวัติการขอย้ายห้อง (ย้ายจากห้อง/เตียงใด ไปห้อง/เตียงใด) |

| 10 | `Maintenance` | ข้อมูลการปิดห้องเพื่อซ่อมบำรุงใหญ่ |
| 11 | `RepairRequests` | รายการแจ้งซ่อมอุปกรณ์ทั่วไป ชนิดปัญหา ความเร่งด่วน ช่างผู้รับผิดชอบ |

| 15 | `AdminUsers` | บัญชีผู้ดูแลระบบ และสิทธิ์การใช้งาน (SuperAdmin, Admin, Staff, Viewer) |

| 17 | `AuditLog` | บันทึกประวัติการเปลี่ยนแปลงข้อมูลสำคัญอย่างละเอียด |
| 18 | `Settings` | ค่าคอนฟิกต่าง ๆ ของระบบ |

## 🛡️ กฎเหล็กของระบบ (System Business Rules)

1. **ห้ามแก้จำนวนผู้พักในห้องโดยตรง:** จำนวนผู้พักต้องคำนวณจาก `Occupancy` ที่มีสถานะ `Active` เท่านั้น
2. **ห้ามลบประวัติการเข้าพักเดิม:** เมื่อมีการย้ายห้องหรือเช็คเอาท์ ให้ปรับสถานะรายการเดิมเป็น `Transferred` หรือ `CheckedOut`
3. **ตรวจสอบความพร้อมของเตียงก่อนเช็คอิน:** ห้ามจัดสรรเตียงที่มีผู้พักอยู่แล้ว หรือพนักงานที่มีห้องพักอื่นอยู่แล้ว
4. **ห้อง Maintenance งดนับเป็นห้องว่าง:** เมื่อห้องอยู่ระหว่างปิดซ่อม ต้องแสดงสถานะเป็นปิดปรับปรุง (สีส้ม) ทันที
5. **Soft Delete:** ข้อมูลสำคัญ (พนักงาน, ห้องพัก) จะใช้วิธีเปลี่ยนสถานะเป็น `Deleted` แทนการลบแถว เพื่อรักษาประวัติใน Audit Log
