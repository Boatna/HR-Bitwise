# 🛒 Employee Marketplace - คู่มือการติดตั้งและใช้งาน (อัปเดต)

เว็บแอปพลิเคชันตลาดซื้อขายออนไลน์สำหรับพนักงานภายในองค์กร
- **Frontend**: HTML5, Tailwind CSS, Vanilla JavaScript (โฮสต์บน **GitHub Pages** ฟรี 100%)
- **Backend & Database**: **Google Sheets** + **Google Apps Script** (จัดการ Database, อัปโหลดรูปภาพลง Google Drive และระบบแชท)

> ฉบับนี้เพิ่ม 3 ฟีเจอร์ใหม่: **(1)** Consent การเปิดเผยข้อมูล (PDPA) **(2)** กติกาการซื้อ-ขายสินค้า **(3)** ระบบจองสินค้าล่วงหน้า (สำหรับหมวด "อาหาร & ขนม") — รายละเอียดอยู่ในหัวข้อ "🆕 ฟีเจอร์ที่เพิ่มใหม่" ด้านล่าง

## 🆕 ฟีเจอร์ที่เพิ่มใหม่

### 1. Consent การเปิดเผยข้อมูล (PDPA)
- เมื่อพนักงานกดปุ่ม **"เข้าสู่ระบบ"** ครั้งแรก (ทุกจุดในระบบ) จะแสดง **หน้าต่างนโยบายความเป็นส่วนตัว (PDPA)** ให้อ่านและติ๊กยอมรับก่อน ถึงจะเข้าสู่ฟอร์มล็อกอินได้ ระบบจะจำการยอมรับนี้ไว้ใน `localStorage` ของเบราว์เซอร์ (ไม่ต้องกดซ้ำทุกครั้ง) และจะถูกบันทึกแนบไปกับ Log การ Login แต่ละครั้งด้วย (คอลัมน์ Details ในชีต `Logs` จะมีข้อความ `[PDPA:ACCEPTED]`)
- สามารถกดดูนโยบายความเป็นส่วนตัวซ้ำได้ทุกเมื่อผ่านลิงก์ **"นโยบายความเป็นส่วนตัว (PDPA)"** ที่ footer ของหน้าเว็บ
- เมื่อลงประกาศขายสินค้าทุกครั้ง ผู้ขายต้องติ๊กยืนยันเพิ่มเติมว่า **ยินยอมเปิดเผยชื่อ-เบอร์โทรศัพท์** ให้ผู้ซื้อที่สนใจติดต่อ (บังคับติ๊กก่อนกดลงประกาศ)

### 2. กติกาการซื้อ-ขายสินค้า
- เพิ่มหน้าต่าง **"กติกาการซื้อ-ขายสินค้า"** เข้าถึงได้จากลิงก์ที่ footer หรือจากฟอร์มลงขายสินค้า (ปุ่ม "กติกาการขายสินค้า")
- ฟอร์มลงขายสินค้าบังคับให้ติ๊กยอมรับกติกาก่อนลงประกาศทุกครั้ง (ใช้ checkbox เดียวกับข้อ 1)
- แก้ไขข้อความกติกาได้โดยตรงในไฟล์ `index.html` ที่ส่วน `<div id="rulesModal">`

### 3. ระบบจองสินค้าล่วงหน้า (เฉพาะหมวด "อาหาร & ขนม")
- เมื่อผู้ขายลงขายสินค้าในหมวด **"อาหาร & ขนม"** จะมีช่อง **"จำนวนสินค้าที่มีขาย"** ปรากฏขึ้นในฟอร์ม (เว้นว่างได้หากไม่ต้องการจำกัดจำนวน)
- สินค้าหมวดนี้จะมีปุ่ม **"จองสินค้า"** ปรากฏในหน้ารายละเอียดสินค้าโดยอัตโนมัติ ผู้ซื้อกรอกจำนวนและหมายเหตุ (เช่น เวลาที่สะดวกมารับ) แล้วส่งคำขอจอง
- ผู้ขายเปิดเมนู **"การจองสินค้า"** (จากเมนูโปรไฟล์มุมขวาบน) เพื่อดูคำขอจองที่ได้รับ และกด **ยืนยัน/ปฏิเสธ** ได้
- ผู้จองสามารถดูสถานะและ **ยกเลิกคำขอจอง** ของตัวเองได้จากแท็บ "รายการที่ฉันจอง" ในหน้าต่างเดียวกัน
- เมื่อยืนยันการจองจนสินค้าครบตามจำนวนที่ระบุไว้ ระบบจะเปลี่ยนสถานะสินค้าเป็น **"ขายแล้ว"** ให้อัตโนมัติ
- ระบบจะสร้างชีตใหม่ชื่อ **`Reservations`** และเพิ่มคอลัมน์ **`Quantity`** ในชีต `Products` ให้ **โดยอัตโนมัติ** ในการเรียกใช้งานครั้งแรก ไม่ต้องสร้างเองด้วยมือ (แต่แนะนำให้เปิด Google Sheet เข้าไปดูหลังใช้งานครั้งแรกเพื่อความมั่นใจ)
- แอดมินสามารถดูรายการจองทั้งหมดในระบบได้ที่แท็บ **"รายการจองสินค้า (Reservations)"** ในหน้า Admin Dashboard (`admin.html`)

**โครงสร้างชีต `Reservations` (สร้างอัตโนมัติ):**

| A | B | C | D | E | F | G | H | I |
|---|---|---|---|---|---|---|---|---|
| **ReservationID** | **ProductID** | **BuyerEmpID** | **SellerEmpID** | **Quantity** | **Note** | **Status** | **CreatedAt** | **UpdatedAt** |

สถานะ (Status) มี 4 ค่า: `PENDING` (รอยืนยัน) / `CONFIRMED` (ยืนยันแล้ว) / `REJECTED` (ผู้ขายปฏิเสธ) / `CANCELLED` (ยกเลิกโดยผู้จอง)

## ⚙️ ขั้นตอนที่ 2: ติดตั้ง Google Apps Script Backend

1. ในหน้า Google Sheets ให้ไปที่เมนูด้านบน: **ส่วนขยาย (Extensions)** > **Apps Script**
2. ลบโค้ดเดิมทั้งหมดในไฟล์ `Code.gs` แล้วนำโค้ดจากไฟล์ **`Code.gs`** ในโปรเจกต์นี้ (ฉบับอัปเดต) ไปวางแทนที่
3. กดบันทึก (Ctrl + S หรือรูปแผ่นดิสก์)
4. ทำการ **Deploy Web App ใหม่** (สำคัญมาก เพราะมีการแก้โค้ด Backend):
   - กดปุ่มสีน้ำเงิน **Deploy (ทำให้ใช้งานได้)** > **Manage deployments (จัดการการทำให้ใช้งานได้)**
   - กดไอคอนดินสอ (แก้ไข) ที่ deployment เดิม แล้วเลือก **Version: New version** จากนั้นกด **Deploy** อีกครั้ง
   - (หากยังไม่เคย Deploy มาก่อน ให้ทำตามขั้นตอนเดิม: **New deployment** > เลือกประเภทเป็น **Web app** > **Execute as: Me** > **Who has access: Anyone** > **Deploy**)
5. คัดลอก **Web App URL** (ที่ลงท้ายด้วย `/exec`) แล้วตรวจสอบว่าตรงกับค่าที่ตั้งไว้ใน `config.js` (`API_URL`) — ถ้า Deploy ใหม่แล้วได้ URL เดิม ก็ไม่ต้องแก้ `config.js`

## 🔗 ขั้นตอนที่ 3: นำ URL ไปเชื่อมต่อในหน้าเว็บ

1. เปิดไฟล์ `config.js` ใน VS Code
2. นำ Web App URL ที่ได้จากขั้นตอนที่ 2 มาใส่ใน `API_URL`:
   ```javascript
   const CONFIG = {
     API_URL: "https://script.google.com/macros/s/AKfycbx.../exec",
     ...
   };
   ```
3. บันทึกไฟล์ `config.js`

## 🌐 ขั้นตอนที่ 4: นำขึ้นโฮสติ้ง GitHub Pages ฟรี

1. สร้าง Repository ใหม่บน [GitHub](https://github.com/new) (เช่นชื่อ `employee-marketplace`)
2. เปิด Terminal ในโฟลเดอร์โปรเจกต์นี้ใน VS Code แล้วรันคำสั่ง:
   ```bash
   git init
   git add .
   git commit -m "Initial commit for Employee Marketplace"
   git branch -M main
   git remote add origin https://github.com/YOUR_USERNAME/employee-marketplace.git
   git push -u origin main
   ```
3. ไปที่หน้า GitHub Repository ของคุณ:
   - ไปที่แท็บ **Settings** > เมนูด้านซ้ายเลือก **Pages**
   - ในหัวข้อ **Build and deployment**:
     - Source: เลือก **Deploy from a branch**
     - Branch: เลือก **main** และโฟลเดอร์ **/(root)**
   - กด **Save**
4. รอประมาณ 1-2 นาที คุณจะได้ลิงก์หน้าเว็บ เช่น:  
   `https://YOUR_USERNAME.github.io/employee-marketplace/`

> เมื่ออัปเดตไฟล์ในอนาคต ให้รัน `git add . && git commit -m "update" && git push` ซ้ำอีกครั้งเพื่อ deploy หน้าเว็บเวอร์ชันใหม่

## 📁 การจัดเก็บรูปภาพสินค้า (Google Drive Folder)

- เมื่อพนักงานลงประกาศขายสินค้าและแนบรูปภาพ ระบบจะทำการย่อขนาดภาพและส่งไปเก็บใน Google Drive ของคุณโดยอัตโนมัติ
- โดยค่าเริ่มต้น ระบบจะสร้างโฟลเดอร์ชื่อ **`Employee_Marketplace_Images`** ใน Google Drive ของคุณ
- หากคุณต้องการระบุโฟลเดอร์ที่มีอยู่แล้ว ให้เปิดโฟลเดอร์นั้นใน Google Drive > คัดลอก ID จาก URL (เช่น `https://drive.google.com/drive/folders/1a2B3c4D5e...`) แล้วนำไปวางในตัวแปร `UPLOAD_FOLDER_ID` ในไฟล์ `Code.gs`:
  ```javascript
  const UPLOAD_FOLDER_ID = '1a2B3c4D5e...';
  ```

## 🛡️ แผงควบคุมผู้ดูแลระบบ (Admin Dashboard & Moderation)

- **การเข้าใช้งาน Admin Dashboard**:
  - พนักงานที่มี EmpID อยู่ในชีต `Admin` (หรือใน `CONFIG.ADMIN_EMP_IDS` เมื่อยังไม่เชื่อมต่อ Backend) จะมีเมนู **"แผงควบคุมผู้ดูแลระบบ (Admin)"** ปรากฏขึ้นในเมนูโปรไฟล์
- **สถิติภาพรวม**: สินค้าที่กำลังขาย, สินค้าที่ขายแล้ว, โพสต์ที่ถูกลบ, จำนวนพนักงานทั้งหมด และ **คำขอจองสินค้าที่รอดำเนินการ (ใหม่)**
- **การจัดการลบโพสต์แปลกๆ/ไม่เหมาะสม (Post Moderation)**: แอดมินสามารถค้นหาและกดปุ่ม **"ลบโพสต์นี้"** พร้อมระบุเหตุผล และบันทึกประวัติการลบลงชีต `Logs` โดยอัตโนมัติ
- **รายการจองสินค้า (ใหม่)**: แท็บ "รายการจองสินค้า (Reservations)" แสดงคำขอจองล่าสุด 100 รายการ พร้อมสถานะ เพื่อให้แอดมินตรวจสอบภาพรวมได้
- **ตรวจสอบประวัติกิจกรรม (System Logs)**: ตรวจสอบประวัติการเข้าสู่ระบบ, การลงขายสินค้า, การส่งข้อความ, การจอง/ยืนยัน/ปฏิเสธการจอง และการจัดการของแอดมินแบบ Real-time

## 🧹 การล้างข้อมูลแชทเมื่อออกจากระบบ (Logout & Memory Optimization)

- เมื่อพนักงานกด **"ออกจากระบบ"** ระบบจะทำการ:
  1. ล้างประวัติแชทที่แสดงในหน้าต่างสนทนา (DOM) ทันที
  2. ล้างข้อมูลการเข้าสู่ระบบ, ข้อมูลแคช และ Session ในเบราว์เซอร์ (`localStorage` และ `sessionStorage`) — **ยกเว้น** สถานะการยอมรับ PDPA ซึ่งจะยังคงจำไว้ (ไม่ต้องกดยอมรับซ้ำทุกครั้งที่ล็อกอินใหม่)
  3. ปิดการเชื่อมต่อ Polling ตรวจสอบข้อความใหม่และคำขอจองสินค้าใหม่ทันที
- สามารถเปิดไฟล์ `index.html` ด้วยเบราว์เซอร์ได้ทันที หรือใช้ส่วนเสริม **Live Server** ใน VS Code เพื่อเปิดทดสอบ
- ระบบมี **Demo Mode** ในตัว หากยังไม่ได้ระบุ `API_URL` ใน `config.js` ระบบจะจำลองข้อมูลสินค้าและแชทให้ทดสอบได้ทันที (ระบบจองสินค้าใน Demo Mode ยังไม่บันทึกข้อมูลถาวร เนื่องจากไม่มี Backend จริงให้เชื่อมต่อ)

## 🔍 สรุปการตรวจสอบและแก้ไขในรอบนี้ (Recheck Notes)

- เพิ่ม Lock/แก้ไข Race Condition ในระบบจองสินค้า: ตรวจสอบจำนวนคงเหลืออีกครั้งทั้งตอนสร้างคำขอจองและตอนผู้ขายกดยืนยัน เพื่อป้องกันการจองเกินจำนวนสินค้าที่มีจริงเมื่อมีผู้ใช้กดพร้อมกัน
- คอลัมน์ `Quantity` ในชีต `Products` และชีต `Reservations` ถูกออกแบบให้ **สร้าง/เพิ่มอัตโนมัติ** เพื่อไม่ให้กระทบผู้ใช้ที่มีชีตเดิมอยู่แล้วและไม่ต้องแก้ไขชีตด้วยมือ
- เมื่อสินค้าถูกจองจนครบจำนวน ระบบจะเปลี่ยนสถานะเป็น "ขายแล้ว" อัตโนมัติ เพื่อไม่ให้มีการจองซ้ำเกินจำนวนจริง
- Consent (PDPA) และกติกาการขายถูกผูกไว้กับทุกจุดที่นำไปสู่การเข้าสู่ระบบหรือลงขายสินค้า เพื่อให้แน่ใจว่าไม่มีช่องทางใดข้ามการยอมรับเงื่อนไขไปได้
- คงพฤติกรรมเดิมของระบบทั้งหมดไว้ (ระบบแชท, การลบ/แก้ไขสถานะสินค้า, การลบโพสต์โดยแอดมิน) ไม่มีการเปลี่ยนแปลงที่กระทบผู้ใช้งานเดิม
